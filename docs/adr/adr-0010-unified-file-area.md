# ADR-0010：统一文件区使用单焦点与安静网格

- Status：accepted
- Kind：architecture
- Date：2026-10-21
- Supersedes：none
- Implements：#193
- 相关：[Research #195](https://github.com/wyz541/kmp-Covio/issues/195)、[Research #198](https://github.com/wyz541/kmp-Covio/issues/198)、[Research #199](https://github.com/wyz541/kmp-Covio/issues/199)、[Research #200](https://github.com/wyz541/kmp-Covio/issues/200)、[Preview #201](https://github.com/wyz541/kmp-Covio/issues/201)

## 背景

截图与临时文件原本属于两个一级工作区。
截图页使用晾衣线和夹子。
文件页使用列表。
两个页面的内容类型、动作和状态不一致。
用户无法在一个工作区完成截图、文件、文本和传输操作。

Covio 还需要遵守 Apple 的「少就是多，多就是少」原则。
界面不能只是把列表换成卡片。
界面不能增加重复的标题、筛选条和检查器。

#201 比较了三版预览：

1. 统一卡片网格。
2. 焦点卡加检查器。
3. 唯一焦点位加安静网格。

第三版在 2026-10-21 通过评审。
评审确认第三版可以落地。

## 决策

1. 一级导航只保留一个「文件」工作区。
2. 默认配置移除「截图」工作区。
3. 「文件」工作区承载截图、图片、普通文件、文本和传输。
4. 五个筛选收进一个筛选菜单，常驻筛选条不显示。
5. 同一时刻只显示一个详细焦点条目。
6. 其余条目显示为四列安静网格。
7. 点击安静网格中的条目，该条目进入焦点位。
8. 原焦点条目退回安静网格。
9. 文件区不显示独立检查器。
10. 元数据和动作通过焦点卡、悬停状态和右键菜单按需出现。
11. 蓝色只用于当前重点、实时状态和主操作。
12. 截图与工作区保留两套持久化模型。
13. 文件区使用只读 `FileAreaItem` 投影，不合并持久化数据。
14. 截图移除只改截图列表，工作区移除删除工作区副本。
15. 传输使用短期运行时任务，不复制内容索引。
16. 工作台配置升到 schema 2。
17. schema 2 迁移移除旧的「截图」工作区。
18. 迁移时保留「文件」的名称、顺序和可见性。
19. 如果旧目的地是「截图」，迁移后进入「文件」的截图筛选。
20. 截图捕获服务继续独立运行，显示入口进入「文件」。
21. 实现使用 SwiftUI 宿主和 KMP 共享投影。
22. 公开库只作行为参考，不定义视觉几何。
23. 设计合同和文案先更新，再实现 SwiftUI 界面。

## 后果

### 正面

- 用户只学一个内容入口。
- 同一屏保留全部内容，详细操作只占用一个焦点位。
- 常驻控件减少，内容获得更多空间。
- 截图原有动作仍可通过焦点卡和右键菜单使用。
- 文件所有权和删除语义保持清楚。
- 旧工作台配置可以迁移，不丢用户顺序。
- 三版预览提供了可比较的视觉证据。

### 负面

- 筛选能力藏在菜单中，首次发现成本高于常驻筛选条。
- 当前焦点切换会重排安静网格。
- 需要维护投影层和两套底层数据模型。
- 需要新增 schema 2 迁移和回归测试。
- 设计合同需要新增或修改文件区组件条目。

### 风险

- 迁移丢失旧工作区配置。缓解：迁移测试覆盖有截图、无截图、隐藏和自定义顺序。
- 原文件与工作区副本语义混淆。缓解：投影记录来源与动作能力，双方运行时分别执行动作。
- 焦点切换导致键盘焦点丢失。缓解：实现任务定义明确焦点顺序并做键盘验收。
- 传输状态重复显示。缓解：一个内容只对应一个条目，状态叠加在条目上。
- 菜单降低筛选可发现性。缓解：筛选按钮显示当前筛选、数量和传输状态。

## 备选方案

### 统一卡片网格

第一版把列表改成同尺寸卡片。
信息层级仍然平。
视觉像通用文件管理器。
未满足差异化和稀缺性。
评审未采用。

### 焦点卡加检查器

第二版用一个焦点卡和一个右侧检查器。
检查器重复了焦点卡的元数据和动作。
常驻界面增加，效率没有同步提高。
评审未采用。

### 合并两套持久化模型

把截图和工作区合并成一个存储模型。
这样会混淆原文件和副本。
删除、移动、过期和远端状态的语义会变复杂。
迁移风险高。
不采用。

### 独立传输队列

为传输增加单独队列或顶级入口。
同一内容会出现在文件卡片和队列中。
条目状态容易分叉。
不采用。

## 落地结果

| 项目 | 结果 |
| --- | --- |
| 焦点切换动效 | 使用 120 毫秒缓出渐隐。减弱动态效果时使用 80 毫秒渐隐。 |
| 键盘网格顺序 | 焦点卡和四列网格按行优先遍历。空格把格子提升到焦点位。 |
| 键盘动作 | Return 执行主操作，Command+C 复制，Command+Delete 删除，M 打开完整动作菜单。 |
| 无障碍 | 可访问名称保留文件名。可访问值包含类型、来源、状态和可用动作。 |
| 传输任务持久化历史 | 首版只维护启动期内存任务。重启后将孤立的 FETCHING 状态恢复为 REMOTE。 |
| 文件区设计合同条目 | 已加入 `component/file-area` 及五个子组件，并重生成 Swift 常量。 |
| 真机宽度 | 960 点和 720 点均使用四列布局。验收图见 `docs/design/previews/231-file-area-960-1.png` 与 `231-file-area-720-1.png`。 |
