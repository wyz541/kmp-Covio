# ADR-0012：默认关闭的实验性合盖零亮度

- Status：accepted
- Kind：architecture
- Date：2026-10-21
- Supersedes：none
- Implements：#203
- 相关：#148、#190、#191

## 背景

Covio 的公开合盖路径只能保持系统运行并关闭显示器。
公开 API 不能把点亮的内建屏设为可见最低亮度。

GitHub 方案审计发现一条私有路径。
路径先由 helper 执行 `pmset disablesleep 1`，再由 `DisplayServices` 设置内建屏亮度。

2026-10-21 在 `MacBookPro18,2`、Apple M1 Max、macOS 27.0.1 上完成探测。
`DisplayServicesGetBrightness` 和 `DisplayServicesSetBrightness` 可动态加载。
连续 5 次写入 `0.0` 并恢复 `0.06250307`，每次回读一致。

该 API 是私有 API。它没有稳定头文件，也没有跨版本兼容承诺。
ADR-0011 的首版范围排除私有亮度接口。
本 ADR 只修改这一条范围限制。

## 决策

1. 新能力默认关闭。用户必须显式开启才能使用。
2. 新能力只作为实验能力展示。界面不得把它描述成稳定的公开能力。
3. 只允许 Apple Silicon 和已验证的 macOS 主版本调用私有符号。首版白名单是 macOS 27。
4. 只在运行时通过 `dlopen` 和 `dlsym` 解析 `DisplayServicesGetBrightness` 与 `DisplayServicesSetBrightness`。
5. 不把 `DisplayServices` 加入链接阶段，也不静态引用私有符号。
6. 只操作内建屏。外接屏在线或状态未知时不写亮度。
7. 缓存最近确认的内建屏 ID。合盖后内建屏离开在线列表时使用缓存 ID。
8. 合盖状态未知时不写亮度。
9. 写入零亮度前，先读取原亮度并原子写入恢复记录。
10. 恢复记录包含显示 ID、原亮度、合盖状态和更新时间。
11. 写入 `0.0` 后立即回读。回读容差是 `0.02`。
12. 开盖、会话结束、配置关闭和应用正常退出时恢复原亮度。
13. 应用启动时读取恢复记录。有效记录优先恢复，然后清除记录。
14. 恢复失败时保留记录，并限制自动重试频率。
15. 私有符号、版本、读取、写入或回读失败时，不报告成功。
16. 私有路径失败时，关闭实验显示接管，并回退到公开合盖关屏路径。
17. 不使用 gamma、遮罩或隐藏窗口伪造硬件亮度。
18. 不复制 GPL-3.0 仓库代码。`Insomnia` 等 MIT 仓库只作为行为和接口证据。
19. 设置页必须显示“实验性”和“可能随 macOS 更新失效”。

## 后果

### 正面

- 用户可以选择“合盖保持运行，内建屏 `0.0`”。
- 私有 API 与默认公开路径隔离。
- 失败路径有明确回退，不伪造成功状态。
- 恢复记录覆盖正常开盖、会话结束、退出和崩溃后的下次启动。
- 版本和符号闸门阻止未验证系统直接调用私有函数。

### 负面

- 私有 API 可能随 macOS 更新失效。
- `0.0` 在视觉上接近黑屏。Covio 不承诺可见画面。
- 当前只确认 macOS 27 和一台 Apple Silicon 机型。
- 恢复记录只能覆盖下次启动。应用崩溃后、下次启动前不能执行恢复。
- App Store 审核风险仍然存在。

### 风险

- 系统在合盖后移除内建屏 ID。缓解：缓存最后确认的内建屏 ID。
- 写入成功但面板没有变暗。缓解：立即回读，超出容差即恢复并回退。
- 恢复记录写成后又发生崩溃。缓解：原子写入；下次启动再次恢复。
- 恢复失败导致屏幕持续过暗。缓解：保留记录、显示错误、限制重试，并允许再次启动恢复。
- 外部显示器被误写。缓解：外接屏存在或未知时禁止私有写入，并使用当前内建屏 ID 校正旧记录。
- 私有函数签名改变。缓解：主版本白名单、动态符号检查和回读验证。

## 备选方案

### 备选 1：只保留公开合盖关屏

不增加私有亮度路径。

未采纳的原因：用户明确要求实验性零亮度能力。该能力已在本机完成写入和恢复可行性测试。

### 备选 2：使用 gamma 或遮罩

把屏幕显示为黑色，不修改硬件亮度。

未采纳的原因：该方案不满足硬件亮度语义，也会影响截图、远程画面和无障碍行为。

### 备选 3：默认开启零亮度

把实验路径作为合盖会话的默认行为。

未采纳的原因：私有 API 稳定性不足。默认开启会扩大系统更新和恢复失败的影响范围。
