# ADR-0014：模型绑定工具在 Agent 响应结束后执行

- Status：accepted
- Kind：architecture
- Date：2026-10-22
- Supersedes：none
- Implements：#242
- 相关：[离线本地服务 Agent 研究](../research/local-agent/README.md)、[#237](https://github.com/wyz541/kmp-Covio/issues/237)

## 背景

Agent 和文件自动命名共用一个本地模型容器。
Agent 在 `ChatSession` 生成期间持有模型租约。
工具调用在生成期间执行。
命名预览需要再次调用同一个模型。
直接嵌套调用会等待自身租约并死锁。

## 决策

1. 工具声明 `immediate` 或 `afterModelResponse` 执行模式。
2. 模型绑定工具在生成期间只排队。
3. 排队结果告诉模型预览已提交。
4. Agent 完成本轮响应后释放模型租约。
5. Agent 在租约释放后执行延迟工具。
6. 延迟工具结果回写会话。
7. 首版只有只读 `preview_file_names` 使用延迟执行。
8. 有副作用工具不得使用延迟自动执行。
9. 延迟队列一次只激活一个调用。
10. 清空会话时清空延迟队列。

## 后果

### 正面

- 避免同一模型租约死锁。
- 保持文件命名和 Agent 共用一个模型容器。
- 延迟工具可以复用现有命名提取和规划逻辑。
- 模型看到预览结果后可以生成自然语言说明。

### 负面

- 一次请求产生两段模型生成。
- 首轮回复可能先说明预览已排队。
- 延迟工具失败需要额外状态回写。

### 风险

- 延迟工具有副作用。缓解：只允许只读工具。
- 队列重复执行。缓解：active slot 和固定 action ID。
- 用户停止后后台执行。缓解：执行阶段禁止停止。
- 模型重复请求预览。缓解：每轮最多执行一个 active call，后续调用继续排队。

## 备选方案

### 允许嵌套租约

嵌套租约会让同一模型并发重入。
KV cache 和 ChatSession 都不支持这种并发使用。
因此不采用。

### 文件命名加载第二个模型

第二个容器会重复占用权重和 KV 内存。
这与共享模型运行时决策冲突。
因此不采用。
