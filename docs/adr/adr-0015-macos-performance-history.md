# ADR-0015：用本地采样支持 macOS 历史性能报告

- Status：accepted
- Kind：architecture
- Date：2026-10-22
- Supersedes：none
- Implements：#266
- 相关：#267、#273

## 背景

Covio 现有 Monitor 页只保存页面可见期间的短时数据。
内存历史只有 60 个点。
电源历史最长 30 分钟和 24 小时。
用户要生成过去 10 天的操作系统与硬件性能报告。

macOS 不提供连续 CPU、GPU、内存、磁盘和网络历史。
统一日志可以补部分事件。
统一日志会按时间和空间轮转。
`powermetrics` 要求 root。
CPU 温度、GPU 温度、风扇和 CPU 频率缺少稳定的公开读取路径。

调研结论和证据见 #267。
推荐契约见 `docs/research/macos-performance-history/solution.md`。

## 决策

1. 首版只支持 macOS。
2. 历史采样使用 Swift 实现，复用现有 Monitor 读取层。
3. 历史存储使用 SQLite3。
4. 数据库路径由 `AppPaths` 提供，放在应用支持目录的 `Monitor/history.sqlite`。
5. 数据库保存 `samples`、`events`、`gaps`、`system_epochs` 四类业务数据。
6. 数据库另保存 schema 版本和迁移信息。
7. 接电源时每 30 秒采样。
8. 使用电池时每 60 秒采样。
9. 供电和热状态变化时立即补样本。
10. 睡眠期间停止采样。
11. 完整唤醒后立即补样本。
12. 采样器记录墙钟、连续时间、boot session 和采集缺口。
13. 采样器在应用运行时工作，不依赖 Monitor 页是否可见。
14. 采样器不保持系统唤醒。
15. 历史模式跳过进程扫描、top app、应用名称、bundle path 和路径解析。
16. 原始样本保留 14 天。
17. 数据库硬上限为 64 MiB。
18. 清理先删除超过 14 天的数据，再从最旧数据开始降到容量上限。
19. 睡眠、唤醒、供电和热状态事件由 Covio 观察并保存。
20. 统一日志只用于尽力补读系统事件。
21. 诊断报告只用于计数和分类，不进入正文。
22. 报告图表使用 5 分钟时间桶。
23. 报告峰值使用原始样本计算。
24. 报告明确显示覆盖率、睡眠区间、未知缺口和不可得指标。
25. 报告首版导出单文件、自包含、离线 HTML。
26. 报告生成不访问网络。
27. 首版不要求 root、helper 或新增 TCC 权限。
28. 首版不采集进程名、文件路径、SSID、BSSID、IP、MAC、序列号和硬件 UUID。
29. 用户可以选择时间范围、导出报告并清除全部历史。
30. 写数据库失败时返回明确错误，不把内存状态冒充为已落盘。
31. 数据库损坏时保留旧文件并建立新库。
32. 报告只描述观察事实，不把相关性写成故障结论。
33. 首版不承诺安装前已经存在 10 天连续性能历史。

## 后果

### 正面

- 用户可以在应用持续运行后导出 10 天性能报告。
- 历史指标不再依赖页面可见时间。
- 数据保留和隐私边界有明确上限。
- SQLite 支持范围查询、事务和有界清理。
- 报告可以离线阅读和打印。
- 首版不增加特权组件和新的系统授权。

### 负面

- 安装后必须等待数据积累。
- 应用退出期间没有性能样本。
- 需要新增数据库迁移、清理和损坏恢复代码。
- 需要维护后台计时器和系统事件监听。
- 首版不能显示温度、风扇和 CPU 频率。

### 风险

- 后台采样影响续航。缓解：30/60 秒周期、跳过进程扫描、实测 CPU 与耗电。
- 数据库持续增长。缓解：14 天和 64 MiB 双上限。
- 睡眠、重启和时钟变化导致错误时间线。缓解：连续时间、boot session、显式缺口。
- 日志接口随系统版本变化。缓解：只补事件，不让核心报告依赖日志。
- 报告泄露隐私。缓解：固定字段白名单、隐私扫描和 HTML 文本转义。
- 10 天覆盖不完整。缓解：显示覆盖率并拒绝把缺失数据写成正常。

## 备选方案

### 备选 1：只读 macOS 系统日志

未采纳的原因：系统日志不提供连续的 CPU、GPU、内存、磁盘和网络时间线。

### 备选 2：使用 SwiftData

未采纳的原因：历史遥测需要明确的表结构、范围查询和容量控制。
SQLite3 的行为更透明，测试更容易确定。

### 备选 3：使用 JSON 文件

未采纳的原因：每次写入要重写文件，范围查询和容量清理成本高。

### 备选 4：用 `powermetrics` 采集更多传感器

未采纳的原因：要求 root，增加安装、授权和安全边界。

### 备选 5：只导出 PDF

未采纳的原因：PDF 分页和图表布局增加首版成本。
自包含 HTML 可以先满足离线阅读和打印。
