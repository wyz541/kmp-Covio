# ADR-0016：用显式开关控制高于上限时的主动放电

- Status：accepted
- Kind：architecture
- Date：2026-10-22
- Supersedes：none
- Implements：#304
- 相关：#137、#162、[充电控制研究](../research/battery-charge-control/README.md)

## 背景

现有充电上限策略在电量高于上限时，把系统目标设为当前电量。
该安全行为避免设备主动放电。
用户需要一个可选行为：接 AC 时使用电池放电到上限。

macOS MCL 在目标低于当前电量时可以让电池放电。
PowerUI 没有公开独立的放电接口。
MCL 单独在电量步进后会把 `70%` 目标恢复为 `80%`。
SMC `CHIE=0x08` 已在真机验证可以强制使用电池。

## 决策

1. 新增本机配置 `chargeLimitActiveDischarge`，默认关闭。
2. 开关关闭时沿用现有行为：高于上限保持当前电量，不主动放电。
3. 开关开启且电量高于上限时，MCL 目标写为用户上限。
4. 电量到达上限后，目标保持在上限，系统停止放电。
5. 电量降到回差阈值后，系统恢复充电到上限。
6. 新增 `discharging` 状态，UI 显示“正在放电至上限”。
7. 主动放电开关必须显示电池循环警告。
8. helper 协议升级为 `8`。客户端必须发送 `activeDischarge` 值。
9. 主动放电只写 SMC `CHIE`：放电写 `0x08`，停止写 `0x00`。
10. 写入失败时恢复原策略，并关闭主动放电意图。
11. 低档位写入删除 `checkpoint` 与 `currentState`，重置 PowerUI 状态机。
12. 主动放电期间 powerd 回退目标时，先等待充电停止。
13. 自动执行 `目标+1` 再写回目标。
14. 自动纠偏最多每 `120` 秒执行一次。
15. helper 退出、恢复默认、关闭开关和到达上限时必须写回 `CHIE=0x00`。
16. `CHIE` 不存在或不可写时，禁用主动放电。

## 后果

### 正面

- 用户可以选择主动放电到上限。
- 默认行为保持安全，不因升级自动放电。
- 复用现有 MCL 写入路径，不增加 SMC 写入。
- helper 状态可以区分保持和主动放电。

### 负面

- 主动放电会增加电池循环。
- `40%` 到 `79%` 仍依赖 root 偏好路径和 powerd 延迟。
- 主动放电依赖机型可写的 SMC `CHIE`。
- 新字段要求重装 helper。
- 需要在 UI 和状态机中增加一个状态。

### 风险

- 用户误开主动放电。缓解：默认关闭、警告、恢复默认时清除开关。
- powerd 未接受低档位目标。缓解：保持 `applying`，不按 `4` 秒判失败。
- 主动放电期间系统目标被外部修改。缓解：进入冲突态并提示用户。
- 睡眠期间继续放电。缓解：目标有上限，系统保护优先，并提供关闭开关。
- 关闭后 powerd 延迟停止放电。缓解：读取电池电流，电流归零前显示 `stoppingDischarge`。
- powerd 在电量步进后恢复旧目标。缓解：限频执行 `目标+1` 再写回目标。
- `CHIE` 写入失败或残留。缓解：读写回验、退出恢复、到达上限恢复和失败关闭。
- 主动放电时适配器字段变为不可见。缓解：以已写入的 `CHIE=0x08` 作为放电状态证据。
- MCL 私有行为变化。缓解：能力检测、回读和失败关闭。

## 备选方案

### 备选 1：只使用 MCL 目标

高于上限时只写 MCL `70%`，等待 powerd 执行。

未采纳的原因：真机在 `79%` 时把目标恢复为 `80%`，系统继续充电。

### 备选 2：始终保持不主动放电

继续把高于上限的目标设为当前电量。

未采纳的原因：用户明确需要高于上限时放电到上限。
该行为保留为默认关闭的显式选项。

### 备选 3：自动默认开启

升级后自动让所有高于上限的设备放电。

未采纳的原因：会改变现有安全行为，并增加意外的电池循环。

## 未决事项

| 项目 | 状态 | 确认方法 |
| --- | --- | --- |
| MCL 主动放电 | 待真机验证 | 检查 `BatteryPower<0` 和到达上限后的状态 |
| 停止放电延迟 | 真机约 `45` 秒 | 读取 `Amperage`，归零前保持 `stoppingDischarge` |
| 睡眠期间行为 | 待验证 | 主动放电中睡眠、唤醒并检查电量 |
| 低档位 `70%` | 待验证 | 按 #162 的 V11 和 V11c 顺序执行 |
| SMC `CHIE` 机型矩阵 | M1 Max 通过 | 验证 macOS 26、Intel 和其他 Apple Silicon |
