# 风扇控制能力补齐

本文定义 #330 风扇能力补齐的交互与组件选择。
本文服务于 #331 预览评审和后续实现 sub-issue。

## 1. 结论

风扇曲线使用 Apple `Swift Charts`。
不手绘曲线 Canvas。
Popover 使用原生 SwiftUI 控件和固定头部。

## 2. 结构

| 区域 | 内容 |
| --- | --- |
| 固定头部 | 控制温度、传感器数量、接管状态、电源来源、夜间状态 |
| 滚动内容 | helper、安全说明、启用开关、模式、曲线或手动转速、风扇读数 |
| 折叠区 | 夜间模式、通知、控制传感器、维护与导航 |
| 固定底部操作 | 恢复系统控制 |

Popover 宽 `420` 点，高 `760` 点。
头部固定。
内容在头部下方滚动。
卡片尺寸和 Monitor 网格不随内容变化。

## 3. Swift Charts

曲线必须使用 `Chart`。

| 元素 | 组件 |
| --- | --- |
| 曲线 | `LineMark` |
| 控制点 | `PointMark` |
| 坐标轴 | `AxisMarks` |
| 拖动命中 | `chartOverlay` + `ChartProxy` |
| 数值编辑 | 原生 `Slider` |

拖动控制点后更新温度和转速。
控制点按温度排序。
每风扇转速限制在 `F%dMn` 到 `F%dMx`。

## 4. 曲线模式

- 全部风扇：同一曲线写入全部风扇。
- 风扇 1：只编辑风扇 1 曲线。
- 风扇 2：只编辑风扇 2 曲线。
- 插电曲线与电池曲线分别保存。
- 电池曲线为空时沿用插电曲线。
- 预设仍提供安静、均衡、强力三档。
- 两点直线是多点曲线的特例。

## 5. 手动模式

- 每个风扇使用独立原生滑杆。
- 单风扇提供全速动作。
- 全局提供全部风扇全速动作。
- 手动值始终限制在硬件范围。

## 6. 夜间模式

夜间模式包含启用开关、开始时间、结束时间和预设。
时间窗支持跨午夜。
生效时显示文字和状态图标。

## 7. 通知

| 通知 | 触发条件 |
| --- | --- |
| 高温 | 控制温度达到用户阈值 |
| 风扇故障 | 目标转速大于 0，实际转速为 0 |

通知有冷却时间。
关闭通知后不发送。

## 8. 传感器

传感器列表显示名称、键名和当前温度。
列表支持按名称或键名筛选。
至少保留一个控制传感器。
完整名称库包含 64 个显式键名。
未知键显示原始四字符键名。

## 9. 无障碍

- 曲线使用 `LineMark` 和 `PointMark` 的原生可访问性。
- 图表提供汇总可访问性值。
- 拖动不是唯一编辑方式。每个控制点同时提供温度和转速滑杆。
- 状态同时显示图标、文字和颜色。
- 所有可点击控件使用原生按钮、开关、分段控件和滑杆。
- 减少动态效果时，滚动定位不使用动画。
