# 上下文

## 问题类别

系统硬件控制能力、权限边界和产品安全。

## 研究问题

macOS 能否安全限制电池充电上限，并进入可验证的旁路供电状态？

## 问题定义

Covio 需要把用户上限转换为系统可执行策略。
系统需要停止电池充电。
系统需要保持适配器供电。
Covio 需要读取真实生效状态。
错误写入不得导致电池、电源或系统状态失控。

## 触发条件

1. 用户启用自定义充电上限。
2. 电池电量达到或高于上限。
3. 系统优化充电与 Covio 上限冲突。
4. 用户恢复系统默认策略。
5. 系统进入睡眠、唤醒、重启或校准周期。
6. 特权 helper 缺失、升级或失败。

## 问题分类

| 类型 | 内容 | 风险 |
| --- | --- | --- |
| 读取 | 读取电量、充电状态、策略和功率 | 低 |
| 策略写入 | 设置上限 | 高 |
| 状态验证 | 确认停止充电和旁路状态 | 中 |
| 恢复 | 交还系统策略 | 高 |
| 兼容性 | OS、硬件和系统更新差异 | 高 |

## 适用范围

1. Apple Silicon MacBook。
2. Intel MacBook 的能力核对。
3. macOS 26 和 macOS 27。
4. 有电池和无电池设备。
5. 有适配器和无适配器。

## 范围外

1. 不修改 SMC 写入值。
2. 不关闭 SIP。
3. 不申请 Apple 私有 entitlement。
4. 不读取序列号。
5. 不验证风扇、温度和 CPU 频率。
6. 不承诺第三方工具的长期稳定性。

## 场景定义

### S1：系统原生上限

系统设置已启用 Manual Charge Limit。
Covio 读取到支持的数值。
Covio 可以请求相同范围内的上限。

### S2：低于原生范围

用户请求小于 `80%`。
原生客户端拒绝该值。
Covio 只能进入特权私有路径，或提示不支持。

### S3：旧 SMC 路径

系统仍暴露 `CH0B` 或 `CH0C`。
特权 helper 可以写入充电禁用状态。
Covio 需要轮询并维护回差。

### S4：能力缺失

没有 MCL，也没有可写 SMC 键。
Covio 必须显示不支持。

## 成功标准

1. 上限值、策略来源和真实状态一致。
2. 旁路状态有独立证据。
3. 用户原有系统策略可以恢复。
4. 失败时不会留下虚假的启用状态。
5. 系统更新后能力变化可以被检测。
