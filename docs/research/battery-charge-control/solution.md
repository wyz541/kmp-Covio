# 推荐方案

## 1. 方案边界

本文只推荐第一阶段的 `80%` 到 `100%` 路径。
本文不批准 `20%` 到 `79%` 的实现。
本文不批准写入 SMC。
本文不批准 root 策略重载。

## 2. 路径选择

| 条件 | 路径 |
| --- | --- |
| MCL 支持，目标不低于 `80%` | 原生 MCL |
| MCL 不支持，旧 SMC 键可用 | 单独评估 SMC |
| MCL 不支持，旧 SMC 键不可用 | 显示不支持 |
| 目标低于 `80%` | 暂不支持 |
| 无电池 | 隐藏入口 |

## 3. 能力检测

只读步骤：

1. 加载 `PowerUI.framework`。
2. 取得 `PowerUISmartChargeClient`。
3. 调用 `isMCLSupported`。
4. 调用 `isMCLCurrentlyEnabled:error:`。
5. 调用 `getMCLLimitWithError:`。
6. 调用 `availableChargeLimitsWithError:`。
7. 读取 `pmset -g battlimit`。
8. 读取 IOPS 和电池功率。

检测失败时关闭功能。
检测失败时不保留旧的“已生效”状态。

## 4. 写入流程

写入前必须由产品批准。

1. 保存原 MCL 开关和上限。
2. 写入 Covio 配置。
3. 调用 `enableMCL:error:`。
4. 调用 `setMCLLimit:error:`。
5. 等待系统注册策略。
6. 读取 `pmset -g battlimit`。
7. 校验目标值。
8. 校验电池充电状态和功率。

如果任一步失败，执行恢复流程。

## 5. 恢复流程

1. 读取保存的原 MCL 开关。
2. 读取保存的原 MCL 上限。
3. 恢复原开关。
4. 恢复原上限。
5. 读取 `pmset -g battlimit`。
6. 校验恢复结果。
7. 恢复失败时保留恢复记录并提示用户。

禁止删除用户原有系统充电上限。

## 6. 外部变更

用户可能从系统设置修改充电上限。
Covio 每次刷新只读检查原生 MCL。

| 检测结果 | 行为 |
| --- | --- |
| 值与 Covio 一致 | 显示生效 |
| 值不同 | 显示外部变更 |
| 原生开关关闭 | 显示系统策略 |
| 校准进行中 | 显示系统临时接管 |
| API 不可用 | 显示不支持 |

Covio 不在用户不知情时反复覆盖系统设置。

## 7. 状态显示

电源卡片显示：

1. 当前电量。
2. 设定上限。
3. 当前策略：Covio 或系统。
4. 状态：充电中、已暂停充电、旁路供电、不支持、恢复失败。
5. 旁路的证据值。
6. 不支持或失败原因。

旁路状态不能只依赖颜色。
旁路状态必须同时显示图标和文字。

## 8. 5% 回差

原生 MCL 不接受回差参数。
Covio 不得显示可配置的 5% 回差。
Covio 不得宣称完全满足 5% 回差。

如果产品坚持 5% 回差，首期方案需要重做。
旧 SMC 路径可以轮询实现回差，但需要单独的硬件写入结论。

## 9. 安全

1. 不向第三方发送电池数据。
2. 不记录序列号。
3. 对私有类做运行时形状检查。
4. 调用失败时 fail closed。
5. 不在未授权时执行写入。
6. 写入前保存原始状态。
7. 写入后回读验证。
8. 恢复失败时保留可重试记录。

## 10. 验收计划

1. 无写入的能力检测。
2. 原生 MCL 状态读取。
3. 原状态保存与恢复。
4. `80` 到 `100` 每个快捷值。
5. 达到上限后停止充电。
6. `BatteryPower=0` 且 `BypassEngaged`。
7. 系统设置外部修改。
8. 睡眠和唤醒。
9. 重启。
10. 校准周期。
11. 无电池设备。
12. Intel 设备。
13. 卸载和 helper 缺失。
14. `bash scripts/test-all.sh` 通过。

详细矩阵见 [validation/README.md](validation/README.md)。
