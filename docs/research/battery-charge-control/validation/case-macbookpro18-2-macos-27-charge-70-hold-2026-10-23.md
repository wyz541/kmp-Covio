# 案例：MacBookPro18,2 在 AC 下保持 70%

## 结果

通过。

Covio 从 `71%` 主动放电到 `70%`。
到达 `70%` 后，`CHIE` 恢复为 `0x00`。
系统目标保持 `70/70`。
AC 已接入，电池停止充电和放电。
连续观察 5 分钟，电量和目标没有变化。

## 环境

| 项 | 值 |
| --- | --- |
| 日期 | 2026-10-23 |
| 硬件 | MacBookPro18,2，M1 Max |
| 架构 | arm64 |
| macOS | 27.0.1 |
| Build | 26A434 |
| App | Debug 构建 |
| 代码基线 | `9d3ceb4` |
| helper 协议 | `8` |

序列号未记录。

## 前置条件

1. 电池上限设为 `70%`。
2. 主动放电开启。
3. AC 已接入。
4. 退出其他 MCL 写入程序。

测试前发现 AlDente 配置为 `80%`。
AlDente 会持续覆盖 PowerUI 目标。
退出 AlDente 后，Covio 才能独占执行目标策略。

## 步骤

1. 读取 helper、`pmset` 和 `ioreg` 的初始状态。
2. 恢复系统目标到 `80%`。
3. 应用上限 `70%`，开启主动放电。
4. 每 30 秒读取电量、系统目标、`CHIE`、电流和供电状态。
5. 电量到 `70%` 后继续观察 5 分钟。
6. 读取最终 helper 和系统状态。

## 观察

主动放电阶段：

| 项目 | 结果 |
| --- | --- |
| 起始电量 | `71%` |
| `CHIE` | `0x08` |
| 供电 | Battery Power |
| 电池电流 | 负值，表示放电 |
| 系统目标 | 放电期间不可见 |

到达上限后：

| 时间点 | 电量 | `CHIE` | 系统目标 | 电池电流 | 供电 |
| --- | --- | --- | --- | --- | --- |
| 到点 | `70%` | `0x00` | `70/70` | 非零尾流 | AC attached |
| 30 秒 | `70%` | `0x00` | `70/70` | `0 mA` | AC attached |
| 5 分钟 | `70%` | `0x00` | `70/70` | `0 mA` | AC attached |

最终 helper 状态：

| 字段 | 值 |
| --- | --- |
| `phase` | `holding` |
| `userLimitPercent` | `70` |
| `targetPercent` | `70` |
| `activeDischarge` | `true` |
| `bypassEngaged` | `false` |

## 结论

Covio 在独占 MCL 时可以保持 `70%`。
AC 为 Mac 供电。
电池不充电到 `80%`。
电池不继续放电。

该结论仅覆盖本轮测试环境和 5 分钟保持窗口。
第三方 MCL 写入程序会改变系统目标。
多个电池管理程序同时运行时，Covio 不能保证目标保持。
