# 上下文与边界

## 1. 问题类别

问题类别是跨平台设备发现、身份认证和受控远程操作。

## 2. 研究问题

Windows 与 macOS Covio 应采用哪种发现、配对、传输和公网接入架构，才能同时覆盖局域网直连与受控远程操作？

## 3. 问题定义

系统需要解决五件事。

1. Windows 找到候选 macOS 设备。
2. 两端建立可信身份。
3. 网络路径覆盖局域网和非局域网。
4. 每条控制命令有明确权限和结果。
5. 断网、离线、越权和能力缺失都能安全恢复。

## 4. 触发条件

以下条件同时成立。

- Windows 客户端使用 KMP 与 CMP。
- macOS 继续使用原生 SwiftUI 宿主。
- 两端都安装 Covio。
- 用户可能处在家庭局域网、公司网络或公网。
- Windows 用户通常是标准账户。
- 远程操作可能改变电源、显示或散热状态。

## 5. 系统模型

| 组件 | 职责 |
| --- | --- |
| Windows 客户端 | 发现设备、发起连接、展示状态、提交受控命令 |
| macOS 主机 | 发布服务、验证身份、执行能力、返回观察结果 |
| 发现层 | mDNS、手动地址、Tailscale/WireGuard 名称 |
| 安全通道 | 配对、证书、TLS、授权和审计 |
| 能力层 | 设备信息、状态读取和写操作 |
| 本机特权层 | 现有 helper 和各能力的系统适配器 |

Windows 不直接连接 macOS 的 Unix 域 socket。Windows 也不直接执行 `pmset`、SMC 或屏幕 API。

## 6. 场景

### 6.1 同一局域网

两台设备连接同一局域网。macOS 用 mDNS 发布服务。Windows 浏览服务并显示设备。用户选择设备并建立连接。

### 6.2 手动地址

mDNS 被防火墙阻断。用户输入 macOS 主机名、IP 或 `host:port`。Windows 建立同一协议连接。

### 6.3 公网

两台设备加入同一 Tailscale tailnet。Windows 使用 MagicDNS 名称或 Tailscale IP 连接 macOS。应用仍执行自己的 mTLS 校验。

### 6.4 首次配对

macOS 显示一次性配对 URI 或二维码。Windows 读取 URI。两端核对设备指纹并建立信任。

### 6.5 已配对设备离线

Windows 显示离线。用户仍能查看上次状态。写操作不可提交。

### 6.6 能力不支持

macOS 无法读取电池、亮度或风扇。设备信息中的能力列表不包含该能力。Windows 禁用对应控件并显示原因。

### 6.7 撤销设备

用户在 macOS 撤销 Windows 设备。后续连接被拒绝。Windows 收到可读的撤销状态。

## 7. 约束

1. macOS 现有 helper 协议不能直接暴露给网络。
2. Windows 不要求管理员权限才能作为客户端运行。
3. 设备发现不能泄露配对秘密。
4. 控制命令必须使用白名单。
5. 远程写操作必须有授权范围。
6. 应用不能把 Tailscale 的 ACL 当作唯一授权。
7. 网络失败不能伪造成功状态。
8. 公开中继不能在首版引入内容存储。
9. 所有网络载荷要有大小上限。
10. 协议要有版本号。

## 8. 成功标准

1. 局域网发现耗时不超过 5 秒。
2. 在线状态在 30 秒内更新。
3. 已配对设备在局域网内接通时间不超过 2 秒。
4. 局域网控制往返时间不超过 300 毫秒。
5. Tailscale 下的控制往返时间不超过 1 秒。
6. 错配对的尝试全部失败并有审计记录。
7. 未授权命令全部被拒绝。
8. 设备撤销在 30 秒内生效。
9. 所有写命令返回观察结果或不支持原因。
10. 网络中断后可以自动重连。
