# 调研过程

## 1. 方法

调研使用四类证据。

1. 现有 Cross-device 内容读取研究。
2. IETF 与 Microsoft 的官方规范。
3. Tailscale 与 Ktor 的官方文档和发布元数据。
4. 当前 macOS 能力实现。

本调研不把未运行的产品行为写成结果。没有端到端实验的项目标记为待验证。

## 2. 局域网发现比较

| 方案 | 优点 | 限制 | 判断 |
| --- | --- | --- | --- |
| mDNS/DNS-SD | 标准、可读名称、低配置 | 多播、权限、防火墙和网络隔离 | 主路径 |
| SSDP | Windows 支持较好 | 面向 UPnP、暴露面大、发现语义较弱 | 不采用 |
| 自定义 UDP 组播 | 可指定网络接口、可控制报文 | 私有协议、需要自测和防火墙规则 | 后续兜底 |
| 手动地址 | 不依赖发现协议 | 用户操作成本高 | 始终保留 |
| Tailscale MagicDNS | 公网可用、名称稳定 | 依赖用户安装 Tailscale | 公网主路径 |

mDNS 使用 `_covio._tcp.local.` 服务类型。TXT 记录只包含设备 ID、协议版本、能力摘要和端口。TXT 记录不包含配对码、证书私钥或用户信息。

手动地址输入同时接受 `host`、`host:port` 和完整 URI。主机名通过 MagicDNS 解析时，用户不需要额外配置 Covio。

## 3. 公网接入比较

| 方案 | 用户配置 | 服务成本 | 隐私边界 | 工程量 | 判断 |
| --- | --- | --- | --- | --- | --- |
| 用户自管 Tailscale | 安装并登录 Tailscale | 低 | 控制面由 Tailscale 提供，数据面为 WireGuard | 中 | 首版首选 |
| 用户自管 WireGuard | 配置端点、密钥和路由 | 低到中 | 自管 | 中到高 | 兼容路径 |
| 自建中继/信令 | 两端只登录 Covio | 高 | Covio 运维方处理连接元数据 | 高 | 后续 |
| 公网端口映射 | 配置路由器 | 低 | 暴露面大 | 低 | 不采用 |

Tailscale 提供 WireGuard 数据面、NAT 穿透和 MagicDNS。Tailscale 的 ACL 是网络层控制。Covio 仍需要应用层配对和能力授权。

WireGuard 本身不会自动提供 NAT 穿透、身份目录或名称服务。用户已有 WireGuard 配置时，Covio 可以把覆盖网络地址当作手动端点。

自建中继需要额外解决认证、限速、滥用防护、可用性、审计和隐私说明。首版不承担这些成本。

## 4. 传输模型

Windows 只发起连接。macOS 监听应用端口。方向固定带来三个结果。

1. Windows 不需要开放入站端口。
2. macOS 防火墙和本地网络权限需要一次授权。
3. Tailscale 下仍然由 Windows 主动连接，符合普通客户端模式。

应用协议采用 JSON-RPC 2.0 语义。传输采用 TLS 1.3 上的 WebSocket。请求、响应和状态事件使用同一协议。

Ktor 3.5.2 的 CIO 服务端、WebSocket 服务端和 CIO 客户端发布物同时提供 `jvm` 与 `macosArm64` 目标。临时 Amper 工程用同一段 CIO 与 WebSocket 代码完成了两端编译。编译结果支持共享传输层，但还不能替代 macOS framework 集成和运行实验。

## 5. 身份与配对

每个设备生成长期身份密钥。设备 ID 取公钥指纹。证书绑定设备 ID。

首版配对使用高熵一次性 URI。macOS 显示二维码和可复制的 URI。Windows 扫描或粘贴 URI。双方核对设备名称和指纹后建立信任。

6 位数字只可以作为可读确认码。6 位数字不能单独承担配对认证。若以后要只用短码，必须采用 PAKE 并限速。

配对完成后保存双方证书。后续连接使用双向 TLS。设备名和 IP 只能帮助用户选择，不能作为身份。

## 6. 授权模型

授权按能力分配，不按设备整体分配。

| 能力 | 默认 | 写操作 | 备注 |
| --- | --- | --- | --- |
| 设备信息 | 允许 | 否 | 主机名、系统版本、Covio 版本 |
| 在线状态 | 允许 | 否 | 心跳和最后在线时间 |
| 电池状态 | 只读授权 | 否 | 数值和充电状态 |
| 充电上限 | 拒绝 | 是 | 依赖 #137 |
| 屏幕亮度 | 拒绝 | 是 | 尚无本机实现 |
| 睡眠 | 拒绝 | 是 | 一次性请求，需要确认策略 |
| 风扇转速 | 拒绝 | 是 | 依赖 #313，必须有租约 |

macOS 保存授权。Windows 只展示 macOS 返回的能力和授权结果。撤销设备后立即关闭会话。

## 7. 控制协议

请求包含以下字段。

| 字段 | 作用 |
| --- | --- |
| `id` | 请求关联 |
| `method` | 白名单方法 |
| `params` | 方法参数 |
| `requestId` | 幂等键 |
| `issuedAt` | 请求时间 |
| `expiresAt` | 过期时间 |
| `expectedState` | 可选，用于防止状态漂移 |

响应必须包含结果或稳定错误码。写操作返回 macOS 观察到的状态。Windows 不能把“请求已发送”显示成“操作已成功”。

## 8. 失败模式

| 失败 | 表现 | 处理 |
| --- | --- | --- |
| mDNS 被阻断 | 设备不出现 | 手动地址 |
| 连接超时 | 设备离线 | 退避重试 |
| 证书不匹配 | 配对失败 | 停止连接并提示风险 |
| 未授权方法 | 拒绝 | 记录审计 |
| 能力缺失 | 控件禁用 | 显示原因 |
| 请求过期 | 拒绝 | 重新读取状态 |
| 参数越界 | 拒绝 | 显示允许范围 |
| helper 失败 | 操作失败 | 返回错误，不假设成功 |
| 设备撤销 | 会话关闭 | 清理本地信任 |

## 9. 反证与未决

1. mDNS 在 Windows 和 macOS 上的实际可用性尚未做双机验证。
2. Tailscale 不需要 Covio 运维服务器，但仍需要用户安装和登录。
3. Tailscale ACL 不能替代 Covio 能力授权。
4. Ktor macOS framework 的导出和运行时尚未做真实服务端实验。
5. 自建中继需要单独研究，不把它写成首版能力。
6. 亮度控制还没有 macOS 本机接口。
7. 风扇控制的租约和恢复必须等 #313 完成。
8. 睡眠操作在锁屏状态下的确认行为需要真机验证。
