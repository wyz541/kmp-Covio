# 推荐方案

## 1. 总体架构

| 层 | 组件 |
| --- | --- |
| UI | Windows CMP 设备列表、设备详情和操作面板 |
| 客户端 | Windows 连接状态机、重试、缓存和请求关联 |
| 主机 | macOS 控制服务、能力路由、审计和授权 |
| 发现 | mDNS 发布/浏览，手动端点 |
| 公网 | Tailscale 或 WireGuard 覆盖网络 |
| 传输 | TLS 1.3 上的 WebSocket |
| 协议 | JSON-RPC 2.0 语义和版本化能力 |
| 身份 | 设备证书、公钥指纹、双向 TLS |

Windows 只作为客户端。macOS 只作为主机。

## 2. 模块建议

| 模块 | 平台 | 职责 |
| --- | --- | --- |
| `kmpDomain` | `jvm`, `macosArm64` | 设备模型、能力值和错误类型 |
| `crossDeviceProtocol` | `jvm`, `macosArm64` | 消息模型、校验、版本和状态机 |
| `crossDeviceTransport` | `jvm`, `macosArm64` | TLS、WebSocket、重连和心跳 |
| `windowsApp` | `jvm/app` | 发现、配对、连接和 CMP UI |
| macOS `RemoteControlHost` | Swift | 生命周期、能力适配、授权和审计 |

协议模块不能依赖 Swift。Swift 宿主通过 KMP framework 调用共享状态机。

## 3. 设备身份

1. 首次启动生成 ECDSA P-256 身份密钥。
2. 证书自签名并包含设备 ID 和显示名。
3. 设备 ID 使用公钥 SHA-256 指纹。
4. 设备名称可以修改，设备 ID 不变。
5. 私钥只保存在应用私有目录和系统保护存储中。
6. 配对时显示指纹短码。
7. 证书轮换需要重新配对或使用旧证书签名的新证书。

## 4. 配对流程

1. macOS 用户打开“添加设备”。
2. macOS 生成一次性配对 URI。
3. URI 包含设备 ID、证书指纹、地址候选和 256 位配对秘密。
4. Windows 扫描二维码或粘贴 URI。
5. Windows 与 macOS 建立临时 TLS 连接。
6. 双方核对设备名称、指纹和确认码。
7. macOS 保存 Windows 证书。
8. Windows 保存 macOS 证书。
9. 配对秘密立即失效。
10. 双方切换到常驻 mTLS 会话。

配对 URI 示例结构如下。

```text
covio://pair?v=1&device=<id>&fingerprint=<sha256>&host=<host>&port=<port>&secret=<token>
```

完整 URI 不写日志。二维码只在配对页面显示。

## 5. 连接流程

1. 读取已配对设备。
2. 优先尝试最近成功的地址。
3. 查询 mDNS 缓存。
4. 尝试手动端点。
5. 建立 TLS 1.3 连接并进行双向认证。
6. 校验协议版本。
7. 拉取设备信息和能力列表。
8. 建立 WebSocket 事件订阅。
9. 每 10 秒发送心跳。
10. 30 秒无响应时标记离线。
11. 使用指数退避重连，上限 60 秒。

## 6. 地址模型

| 路由类型 | 示例 | 来源 |
| --- | --- | --- |
| LAN | `192.168.1.20:47837` | mDNS 或手动 |
| Tailnet | `mac-mini.tailnet.ts.net:47837` | MagicDNS 或手动 |
| WireGuard | `10.10.0.2:47837` | 用户输入 |
| Relay | 暂未实现 | 后续扩展 |

地址不是身份。证书校验失败时，切换地址也不能继续。

## 7. 协议

### 7.1 消息

| 方法 | 类型 | 作用 |
| --- | --- | --- |
| `device.describe` | 读 | 主机名、系统、Covio 版本和能力 |
| `state.get` | 读 | 获取当前状态快照 |
| `state.subscribe` | 读 | 订阅状态变化 |
| `power.chargeLimit.set` | 写 | 设置充电上限 |
| `display.brightness.set` | 写 | 设置屏幕亮度 |
| `power.sleep.request` | 写 | 请求睡眠 |
| `thermal.fan.set` | 写 | 设置风扇目标 |

### 7.2 请求示例

```json
{
  "jsonrpc": "2.0",
  "id": "7f7d",
  "method": "power.chargeLimit.set",
  "params": {
    "requestId": "b8b0e5b0",
    "issuedAt": "2026-10-24T02:00:00Z",
    "expiresAt": "2026-10-24T02:00:10Z",
    "value": 80,
    "expectedState": {
      "currentLimit": 100
    }
  }
}
```

### 7.3 响应要求

1. 写请求返回 `accepted`、`rejected` 或 `unsupported`。
2. `accepted` 必须附带观察到的状态。
3. 所有错误使用稳定错误码。
4. 请求超时后客户端重新读取状态。
5. 相同 `requestId` 重试不能重复执行非幂等操作。

### 7.4 错误码

| 错误码 | 含义 |
| --- | --- |
| `protocol_version_unsupported` | 协议版本不兼容 |
| `device_revoked` | 设备已撤销 |
| `capability_denied` | 未授权能力 |
| `capability_unsupported` | 本机不支持 |
| `invalid_argument` | 参数越界 |
| `request_expired` | 请求过期 |
| `state_conflict` | 预期状态不一致 |
| `helper_unavailable` | 本机特权服务不可用 |
| `operation_failed` | 本机操作失败 |
| `rate_limited` | 请求过多 |

## 8. 能力边界

### 8.1 设备信息与状态

主机名、macOS 版本、Covio 版本、在线状态和最后在线时间可以默认只读。电池状态需要读取能力。

### 8.2 充电上限

依赖 #137 完成。允许值沿用本机策略。远程请求不能绕过硬件保护、温度保护和系统策略。恢复默认值必须有独立命令。

### 8.3 屏幕亮度

需要先增加 macOS 本机亮度控制。取值范围使用归一化 `0.0` 到 `1.0`。0 亮度必须明确提示。该功能在完成本机验收前保持 `capability_unsupported`。

### 8.4 睡眠

睡眠属于高风险操作。macOS 必须允许用户关闭远程睡眠。启用时，每次请求包含过期时间。锁屏时是否允许执行需要真机验证。

### 8.5 风扇转速

依赖 #313。只有 #313 通过安全验收后才开放。远程命令使用 20 秒租约。租约到期、连接断开、三次写入失败或 helper 退出时恢复系统控制。远程请求不能把目标转速设到硬件范围外。

## 9. 授权

1. 配对后默认只有 `device.describe` 和在线状态。
2. 每项能力单独授权。
3. 写能力授权在 macOS 本机完成。
4. 授权包含设备、能力、范围和创建时间。
5. 用户可以在 macOS 查看和撤销。
6. 撤销会关闭当前会话。
7. 任何权限变化写入本地审计日志。

## 10. 安全设计

1. 只接受 TLS 1.3。
2. 双向证书认证。
3. 证书指纹固定并绑定设备 ID。
4. 帧大小上限为 64 KiB。
5. 请求过期时间不超过 10 秒。
6. 写请求带幂等键。
7. 服务端按方法白名单路由。
8. 禁止通用 shell、脚本和文件路径参数。
9. 每个设备有请求速率上限。
10. 失败尝试写入审计日志。
11. Tailscale ACL 是附加层，不是替代层。
12. 日志不记录配对秘密和证书私钥。

## 11. 状态与恢复

1. 在线表示 30 秒内收到有效响应。
2. 离线状态保留最后成功快照和时间。
3. 网络切换后重新解析地址。
4. 设备撤销后清除缓存的在线状态。
5. 协议不兼容时禁止降级到未认证通道。
6. helper 不可用时只禁用对应能力。
7. 睡眠后连接由设备离线处理。

## 12. 验收

1. 局域网发现和手动连接通过。
2. Tailscale 远端连接通过。
3. 配对 URI 可以使用。
4. 错误配对秘密失败。
5. 证书不匹配失败。
6. 未授权能力失败。
7. 撤销设备后连接关闭。
8. 只读状态稳定。
9. 充电、亮度、睡眠和风扇分别验收。
10. 断网、重连和离线状态通过。
11. 所有失败返回稳定错误码。
12. `bash scripts/test-all.sh` 通过。

## 14. 回滚条件

满足任一条件时，暂停对应能力上线。

1. 证书或配对流程有未解决的高风险缺陷。
2. Tailscale 路径无法区分设备身份。
3. 远程命令可绕过能力白名单。
4. 写操作无法返回真实状态。
5. 风扇租约不能恢复系统控制。
6. 睡眠请求可能在没有提示时触发。
7. 撤销设备后连接仍然有效。
8. 真实设备无法稳定重连。

## 15. 自建中继的保留接口

首版只保留接口，不实现服务器。

1. 消息按设备 ID 路由，不按 IP。
2. 传输层可替换为 WSS 中继。
3. 应用层保持端到端加密和双方认证。
4. 中继不保存控制内容。
5. 中继只保存短期在线状态和路由元数据。
6. 中继协议单独写 ADR 和隐私说明。
