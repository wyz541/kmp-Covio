# 结论与限制

> 结论：专注模式应做成五个可编辑模板。完整模板用 Shortcuts 控制 macOS Focus。Covio 只自动执行可恢复的公开接口动作。

## 1. 结论摘要

1. 提供 video、game、coding、work、study 五个内置模板。
2. 模板允许用户改名、增删应用和执行高级 Shortcut。
3. 完整模板需要进入和退出两个 Focus Shortcut。
4. 缺少 Focus Shortcut 时阻止正常进入。
5. 用户可在明确警告后选择不含 Focus 的降级进入。
6. 应用动作默认使用隐藏。
7. 请求退出是逐应用显式开关。
8. Covio 禁止强制退出应用。
9. 保持屏幕唤醒使用时限租约。
10. 首版不修改音量、亮度、网络、蓝牙、风扇和窗口布局。
11. 会话开始前写入恢复日志。
12. 会话退出时按逆序恢复。
13. 恢复失败时保留日志并显示恢复入口。
14. 首版不申请 Accessibility 或 Screen Recording 权限。

## 2. 决策因素

### 2.1 主要因素

#### 2.1.1 Focus 写入边界

macOS SDK 公开读取 Focus 状态。
macOS SDK 不公开写入 Focus。
Shortcuts 提供 `Set Focus` 动作。
Shortcuts 可以运行用户创建的 Focus 控制入口。

因此 Focus 写入交给 Shortcuts。
Covio 不模拟 Control Center。
Covio 不调用私有 Focus 框架。

证据链见 E-02 至 E-08。

#### 2.1.2 数据丢失风险

退出应用会影响未保存数据。
隐藏应用不会关闭文档。
请求退出仍可能触发保存提示。
强制退出会跳过保存提示。

因此默认动作使用隐藏。
请求退出需要逐应用开启。
强制退出不提供。

证据链见 E-09、E-10。

#### 2.1.3 可恢复性

系统动作必须能撤销或明确标为外部动作。
Covio 能恢复自己的睡眠断言和应用隐藏状态。
Covio 不能保证恢复 Shortcut 的任意副作用。

因此恢复日志必须在动作前写入。
外部动作必须在 UI 中说明。

证据链见 E-04、E-11、E-18。

### 2.2 次要因素

1. 用户创建 Focus 和 Shortcut 有配置成本。
2. 五个模板能覆盖用户给出的主要场景。
3. 模板可编辑，避免硬编码应用列表。
4. 限时会话能降低电池和热风险。
5. 按当前电源策略增加租约，避免覆盖已有唤醒请求。

## 3. 根因证据链

```text
问题：需要切换多种专注配置
  -> Apple Help：Focus 支持 Work、Gaming 和 Custom
  -> SDK：Focus 状态可读，写入未公开
  -> Shortcuts：提供 Set Focus 动作和 CLI
  -> AppKit：应用可启动、隐藏和请求退出
  -> AppKit：forceTerminate 会丢失数据风险
  -> IOKit：可用断言保持屏幕唤醒
  -> Covio：已有 HoldLeaseManager 可管理多来源租约
  -> 决策：Shortcuts 管 Focus，公开接口管应用和电源
```

## 4. 决策表

| 决策 | 选择 | 原因 | 备选路径 |
| --- | --- | --- | --- |
| 模式集合 | video、game、coding、work、study | 覆盖用户示例和常见场景 | 允许复制为自定义模板 |
| 模板来源 | 内置模板可编辑 | 避免硬编码个人应用 | 固定不可改模板 |
| Focus 控制 | Shortcut | 唯一稳定的用户可配置写入路径 | GUI 自动化或私有接口 |
| Focus 绑定 | 完整模板需要进入和退出 Shortcut | 进入和退出责任清楚 | 单 Shortcut 切换 |
| 缺少 Focus | 阻止正常进入 | 避免显示成功但通知未静音 | 静默降级 |
| 降级运行 | 明确确认后可进入 | 保留用户选择 | 完全禁止 |
| 应用关闭 | 默认隐藏 | 降低数据丢失风险 | 直接请求退出 |
| 请求退出 | 逐应用显式开启 | 用户知道哪些应用可退出 | 全模板统一退出 |
| 强制退出 | 禁止 | 数据丢失风险高 | 无 |
| 保持唤醒 | 限时租约 | 降低电池和热风险 | 永久断言 |
| 唤醒所有者 | `HoldLeaseManager` 新来源 | 不覆盖已有规则 | 直接调用单断言端口 |
| 默认会话时长 | 2 小时 | 覆盖多数专注时段 | 用户修改 |
| 最大会话时长 | 8 小时 | 限制失控风险 | 用户延长 |
| 音量 | 不改 | 会影响视频和游戏播放 | 用户 Shortcut |
| 亮度 | 不改 | 公开接口不足 | 私有接口 |
| Wi-Fi | 不改 | 会中断网络和远程会话 | 用户 Shortcut |
| 蓝牙 | 不改 | 没有稳定公开写入接口 | 用户 Shortcut |
| 壁纸 | 后期可选 | 有公开接口，但恢复复杂 | 首版不做 |
| 窗口布局 | 不做 | 需要辅助功能权限且不稳定 | 用户 Shortcut |
| 恢复日志 | 动作前原子写入 | 支持崩溃恢复 | 只在内存记录 |

## 5. 不采用方案

| 方案 | 风险 | 不采用原因 |
| --- | --- | --- |
| Control Center GUI 自动化 | Accessibility 授权、菜单变化、焦点依赖 | 不稳定且权限成本高 |
| 私有 Focus 框架 | 无兼容承诺，可能触发审核问题 | 不可维护 |
| 模拟通知开关 | 无法完整覆盖 Focus 过滤和允许列表 | 与系统行为冲突 |
| 直接退出所有非允许应用 | 未保存文件可能丢失 | 风险不可接受 |
| 强制退出应用 | 数据丢失 | 禁止 |
| 修改全局音量 | 视频和游戏会被静音 | 动作语义错误 |
| 修改 Wi-Fi 或 VPN | 消息、同步和远程会话会中断 | 副作用过高 |
| 用常驻无限睡眠断言 | 电池耗尽、热风险和意外过夜 | 改用限时租约 |

## 6. 系统限制

1. macOS 没有公开的 Focus 创建接口。
2. macOS 没有公开的 Focus 名称读取接口。
3. `INFocusStatusCenter` 只返回布尔状态。
4. `INFocusStatusCenter` 读取需要用户授权。
5. Shortcuts 名称和内容由用户维护。
6. 应用隐藏状态可能被应用自身改变。
7. 请求退出可能被保存提示阻止。
8. 用户主动睡眠不受空闲断言阻止。
9. 私有亮度接口没有兼容承诺。
10. 蓝牙开关没有稳定的公开写入接口。

## 7. 产品限制

1. 首版要求用户创建 Focus 和 Shortcut。
2. 首版没有自动切换窗口布局。
3. 首版没有自动调整亮度和音量。
4. 首版没有跨设备同步。
5. 首版没有自动写入 macOS Focus。
6. 首版没有 Mac App Store 分发方案。
7. 外部 Shortcut 的副作用由用户负责。
8. 应用退出后不会自动重启已关闭的应用。
