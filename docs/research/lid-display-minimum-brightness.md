## 问题

Apple Silicon 内建屏能否在合盖后保持点亮，并设置为最低亮度？

## 结论

公开 API 路径不支持“内建屏点亮并降到可见最低亮度”。

GitHub 审计发现了一条私有 API 路径：`disablesleep` 保持系统运行，再用 `DisplayServicesSetBrightness(0)` 把面板压暗，同时保留 framebuffer。
2026-10-21 的本机写入、回读和恢复探针通过。
ADR-0008 接受该路径作为默认关闭的实验能力。
`0.0` 在视觉上接近黑屏，不是可见的最低亮度画面。
完整仓库对比见 `github-lid-brightness.md`。

Covio 支持“合盖保持运行，内建屏关闭”。
Covio 默认不支持“合盖保持运行，内建屏点亮并降到最低亮度”。
Covio 只提供显式开启的实验性“内建屏 `0.0`”路径。

## 依据

1. `IOPMLib.h` 没有合盖显示保持断言。
2. 公开断言只覆盖空闲系统睡眠和空闲显示器睡眠。
3. 内建屏在合盖后受硬件 clamshell 状态管理。
4. Apple M1 Max 上直接调用公开 IOKit 亮度接口返回 `kIOReturnUnsupported`。
5. 可用的内建屏亮度接口依赖私有 `DisplayServices`。
6. ADR-0007 首版不接私有亮度 API。
7. ADR-0008 只接受默认关闭的实验路径，不接受稳定能力承诺。

## 决策

1. 默认 UI 使用“合盖关屏”，不显示“最低亮度”成功状态。
2. 不用 gamma 黑屏、遮罩或隐藏窗口冒充硬件亮度。
3. 不把外接屏行为标成内建屏行为。
4. 外接屏保持点亮需要单独产品需求。
5. 实验路径默认关闭，只对已验证的 Apple Silicon 和 macOS 主版本启用。
6. 私有路径失败时回退“合盖关屏”，不报告零亮度成功。

## 可行性与稳定性验证

### 环境

| 项目 | 值 |
| --- | --- |
| 机型 | `MacBookPro18,2` |
| 芯片 | Apple M1 Max |
| 架构 | `arm64` |
| macOS | 27.0.1 |
| 构建号 | 26A434 |
| 内建屏 ID | `1` |

### 只读探测

`DisplayServicesGetBrightness` 返回 `0`。
原始亮度回读为 `0.06250307`。
`DisplayServicesSetBrightness` 符号存在，只读探测未修改亮度。

### 写入和恢复

连续执行 5 次以下序列：

```text
读取原亮度
→ 写 0.0
→ 回读 0.0
→ 写回原亮度
→ 回读原亮度
```

结果：

| 次数 | 写零结果 | 零亮度回读 | 恢复结果 | 恢复回读 |
| --- | --- | --- | --- | --- |
| 1 | `0` | `0.00000000` | `0` | `0.06250307` |
| 2 | `0` | `0.00000000` | `0` | `0.06250307` |
| 3 | `0` | `0.00000000` | `0` | `0.06250307` |
| 4 | `0` | `0.00000000` | `0` | `0.06250307` |
| 5 | `0` | `0.00000000` | `0` | `0.06250307` |

5 次写入和恢复均通过。
验证后再次回读原亮度，结果为 `0.06250307`。

### 合盖矩阵

2026-10-21 在合盖保持会话中完成以下检查：

| 阶段 | 结果 |
| --- | --- |
| 合盖状态 | `AppleClamshellState = Yes` |
| helper 租约 | 持续续租 |
| `SleepDisabled` | `1` |
| 内建屏状态 | 在线、活动、未睡眠 |
| 亮度 | 连续 6 次采样均为 `0.0` |
| 恢复记录 | 合盖期间存在，内容包含原亮度、显示器 ID 和合盖状态 |
| 开盖状态 | `AppleClamshellState = No` |
| 开盖恢复 | 恢复记录被清除，应用继续运行 |
| 会话结束 | `SleepDisabled = 0`，所有权文件不存在 |

一次故障恢复矩阵的原始亮度是 `0.41988200`。
强制终止应用后，亮度保持 `0.0`，恢复记录保留。
重新启动应用后，亮度回读为 `0.41988200`，恢复记录被清除。
旧 helper 租约在 14 秒内到期，`SleepDisabled` 回到 `0`。
