## 目标

比较 Qwen3-VL 2B、4B、8B 和 30B-A3B 的 4bit 版本。
比较工具选择、命名质量、加载速度、生成速度和内存。
给出默认档、低内存档和高质量档。

## 模型包

| 模型 | 文件总大小 |
| --- | ---: |
| `Qwen3-VL-2B-Instruct-4bit` | `1,798,024,507` bytes |
| `Qwen3-VL-4B-Instruct-4bit` | `3,109,732,804` bytes |
| `Qwen3-VL-8B-Instruct-4bit` | `5,776,633,868` bytes |
| `Qwen3-VL-30B-A3B-Instruct-MLX-4bit` | `18,268,092,893` bytes |

全部模型文件通过 ModelScope API SHA-256 校验。

## 工具矩阵

矩阵包含 30 个请求。
矩阵覆盖 8 个工具、普通对话和安全攻击。

| 模型 | 匹配 | 准确率 | 错误 | 未授权副作用 | 总耗时 | 加载 | 峰值 RSS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2B | 27 / 30 | 90.0% | 1 | 0 | `60,210.3` ms | `1,401.6` ms | `2,076,311,552` bytes |
| 4B | 30 / 30 | 100% | 1 | 0 | `111,234.8` ms | `1,546.0` ms | `3,399,188,480` bytes |
| 8B | 29 / 30 | 96.7% | 0 | 0 | `152,228.9` ms | `1,526.4` ms | `6,062,309,376` bytes |
| 30B-A3B | 未完成 | — | 崩溃 | 0 | — | — | — |

4B 的 error 是模型请求 `open_settings(page: mars)`。
严格 schema 正确拒绝了这个调用。
这次 error 不计为匹配失败。

8B 没有调用工作区工具来回答“列出工作区里的三个最大文件”。

2B 有三个失败：

1. 没有选择 `copy_text`。
2. 工作区请求生成了 malformed JSON。
3. “火星设置”生成了不存在的页面参数。

30B-A3B 在 tool-calling 路径触发以下崩溃：

```text
MLX/ErrorHandler.swift:345: Fatal error: SmallVector out of range.
```

四个模型都能生成可用的文本和图片标题。
4B 在工具选择和命名质量之间取得最好平衡。

## 运行时结论

30B-A3B 的无工具命名路径通过。
30B-A3B 的 tool-calling 路径不可用。
该崩溃发生在 `mlx-swift-lm` 的 Swift tool-calling 路径。
因此 30B-A3B 不能作为 Agent 生产模型。

8B 的文件更大、生成更慢、峰值内存更高。
8B 在这 30 条样本中也没有提高工具准确率。
因此 8B 不设为默认模型。

## 决策

| 硬件 | 模型 | 状态 |
| --- | --- | --- |
| 8–12 GB | `Qwen3-VL-2B-Instruct-4bit` | 低内存回退 |
| 16 GB 以上 | `Qwen3-VL-4B-Instruct-4bit` | 默认 |
| 24 GB 以上 | `Qwen3-VL-8B-Instruct-4bit` | 可选，需后续评测 |
| 32 GB 以上 | `Qwen3-VL-30B-A3B-Instruct-4bit` | 暂缓 Agent 路径 |

## 清理记录

1. 模型下载目录位于任务 scratch。
2. 模型文件通过固定 SHA-256 校验。
3. 测试只使用合成请求。
4. 测试不包含用户文件。
