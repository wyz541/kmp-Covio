# 结论与限制

> 本文件承载结论摘要、决策因素、决策表、不采用方案、限制和未决项。

## 1. 结论摘要

Covio 无法在事后从 macOS 完整重建过去 10 天的连续性能历史。
macOS 能补充部分系统事件。
CPU、GPU、内存、磁盘、网络、电池和热压力的连续时间线必须由 Covio 自己采样并保存。

首版采用以下方案：

1. SQLite3 本地存储。
2. 接电源每 30 秒采样一次。
3. 使用电池每 60 秒采样一次。
4. 供电和热状态变化时立即补样本。
5. 保留 14 天，硬上限 64 MiB。
6. 输出自包含 HTML 报告。
7. 报告明确显示覆盖率、睡眠区间和采集缺口。
8. 不需要 root、helper 或新增 TCC 权限。

## 2. 主要决策因素

### 2.1 系统历史不足

macOS 没有公开的连续 CPU、GPU、内存、磁盘和网络历史接口。
现有 Covio 监控也只保存 60 个内存点。
因此安装后第一次请求 10 天报告，不能得到完整结果。

证据链：

```text
E-09 现有监控指标读取路径
  -> E-10 页面可见才采样
  -> E-11 内存历史只有 60 点
  -> E-12 电源历史最长 30 分钟和 24 小时
  -> E-14 SQLite 容量可接受
  -> 决策：Covio 自己持久化历史
```

### 2.2 系统事件可作为补充

统一日志在本机 10 天前仍有条目。
`OSLogStore` 是公开 API，但要求管理员账号，且日志会轮转。
因此日志适合补充睡眠、唤醒、重启和异常事件。
日志不适合作为主要性能时间线。

证据链：

```text
E-02 10 天前窗口有日志条目
  -> E-04 日志会按时间和空间轮转
  -> E-19 OSLogStore 要求管理员账号
  -> 决策：事件尽力补读，核心指标自行采样
```

### 2.3 采样成本可接受

完整读取当前监控快照平均消耗 15.685 ms CPU。
30 秒周期摊薄后是 0.052% 单核 CPU。
后台采样还会跳过进程和 top app 扫描，因此成本应不高于该值。

证据链：

```text
E-09 已有读取器
  -> E-13 单次读取成本
  -> 决策：接电源 30 秒，使用电池 60 秒
```

### 2.4 存储成本很小

14 天、30 秒间隔的 40,320 条合成样本占 6.36 MiB。
范围查询与小时聚合耗时约 0.02 秒。
SQLite 足以支撑 14 天样本和报告生成。

证据链：

```text
E-14 容量与查询测试
  -> 决策：SQLite，14 天，64 MiB 上限
```

## 3. 决策表

| 决策 | 选择 | 原因 | 备选路径 |
| --- | --- | --- | --- |
| 报告数据来源 | Covio 持久化采样 | 系统没有连续性能历史 | 增加系统日志补读 |
| 历史事件来源 | 自身事件记录加尽力补读 | 睡眠和重启需要边界 | 只使用应用事件 |
| 存储引擎 | SQLite3 | 事务、范围查询、容量小、可检查 | SwiftData |
| 接电源采样 | 30 秒 | 保留短时峰值，成本低 | 60 秒 |
| 使用电池采样 | 60 秒 | 降低后台唤醒 | 5 分钟 |
| 事件采样 | 立即 | 保留状态变化 | 等下一次周期 |
| 原始保留 | 14 天 | 覆盖 10 天并留 4 天缓冲 | 10 天 |
| 容量上限 | 64 MiB | 远高于实测占用 | 无上限 |
| 导出格式 | 自包含 HTML | 可离线阅读和打印，依赖少 | PDF |
| 进程数据 | 不采集 | 隐私边界更小 | 用户显式开启 |
| 温度指标 | 不承诺 | 公开接口不足 | 使用私有接口 |
| 后台运行 | 应用运行即采样 | 报告依赖覆盖 | 只在报告页采样 |
| 权限 | 不新增 root 或 TCC | 公开接口足够 | helper |
| 缺失处理 | 显示缺口 | 防止假数据 | 补齐为零 |

## 4. 不采用方案

### 4.1 只读系统日志

风险：日志按空间轮转，无法保证 10 天；也没有连续 CPU、GPU、内存、磁盘和网络数据。
不采用原因：不能支撑主要报告。

### 4.2 新增特权 helper 运行 `powermetrics`

风险：增加安装、授权、安全、公钥和崩溃恢复边界。
不采用原因：首版指标可以用无特权公开接口获得。

### 4.3 解析旧 ASL 电源文件

风险：ASL 从 macOS 10.12 起废弃，文件格式大，苹果不保证继续支持。
不采用原因：不能满足可维护性要求。

### 4.4 使用 JSON 数组保存样本

风险：每次写入要重写大文件，损坏恢复差，查询需要全量加载。
不采用原因：14 天样本虽然小，但范围查询和保留策略更适合 SQLite。

### 4.5 只在使用报告时采样

风险：用户打开报告时，过去的数据已经不存在。
不采用原因：不能回答历史问题。

### 4.6 导出 PDF 作为首版唯一格式

风险：图表分页、字体和打印布局需要额外调试。
不采用原因：自包含 HTML 可以先满足阅读和打印需求；PDF 作为后续格式。

## 5. 系统限制

1. 安装 Covio 前没有连续性能历史。
2. macOS 统一日志会轮转。
3. 普通用户不能运行 `powermetrics`。
4. `pmset -g log` 是调试接口。
5. CPU 温度、GPU 温度、风扇和 CPU 频率没有稳定的公开读取路径。
6. 睡眠期间不会产生连续样本。
7. Intel 与台式机能力需要单独验证。

## 6. 产品限制

1. 首版报告不展示进程级排名。
2. 首版报告不诊断硬件故障。
3. 首版不承诺 10 天数据一定完整。
4. 首版需要应用在报告范围内运行。
5. 首版输出 HTML，不直接输出 PDF。
6. 首版只支持 macOS 26 及以上。
