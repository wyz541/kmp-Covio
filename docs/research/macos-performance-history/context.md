# 前因与问题边界

> 本文件承载问题类别、研究问题、范围、系统模型、状态矩阵、场景和成功标准。

## 1. 问题类别与研究问题

### 1.1 问题类别

本研究的类别是「历史遥测能力与本地留存」。
这类问题问的是：过去发生的数据是否存在，应用能否补读，补读后是否足以支持一段时间范围的事实报告。

类别不绑定 Covio。
任何要生成历史性能报告的应用，都面对系统历史、应用采样和留存成本三个问题。

### 1.2 研究问题

主问题：要生成过去 10 天的 macOS 性能和硬件报告，Covio 应保存哪些指标，采样和留存策略是什么？

### 1.3 问题定义

用户连续 10 天高强度使用 Mac。
用户要解释这段时间 CPU、GPU、内存、磁盘、网络、电源、电池、热压力和睡眠唤醒发生了什么。
macOS 不保证保留这些指标的连续历史。
因此报告的可信度取决于两件事：系统能提供什么事件历史，Covio 自己保存了什么采样历史。

### 1.4 触发条件

以下任一情况触发本研究。

1. Covio 要支持 10 天历史性能报告。
2. Covio 要从实时监控进入后台采样。
3. 报告要声明数据覆盖率和缺口。
4. 报告要导出到本机文件。
5. 采样策略影响电池续航、磁盘占用或隐私边界。

## 2. 范围

### 2.1 适用范围

| 项目 | 范围 |
| --- | --- |
| 平台 | macOS 26 及以上 |
| 机型 | Apple Silicon 笔记本优先 |
| 报告范围 | 最近 10 天，最长保留 14 天 |
| 指标 | CPU、GPU、内存、磁盘、网络、电池、电源、热压力和系统事件 |
| 数据源 | 现有 `MacMonitorReader`、公开系统 API、统一日志、诊断报告 |
| 输出 | 本机自包含 HTML 报告 |
| 权限 | 不要求 root、helper 或新增 TCC 权限 |

### 2.2 范围外事项

1. CPU 温度、GPU 温度、风扇转速和 CPU 频率。
2. 进程名、进程路径、窗口标题、文件路径和网络载荷。
3. 网络远端监控和多机聚合。
4. 故障诊断结论和硬件维修建议。
5. 实时监控页的视觉重做。
6. Windows 和 iOS 的实现。

## 3. 受影响角色

| 角色 | 关心什么 |
| --- | --- |
| 用户 | 报告能否解释过去 10 天的异常 |
| 产品 | 哪些指标可以承诺，缺口如何表达 |
| 研发 | 系统历史是否可靠，数据存到哪里 |
| 测试 | 睡眠、重启和长时段数据是否连续 |
| 安全与合规 | 是否采集进程、网络和用户内容 |
| 支持 | 报告能否稳定复现和解释 |

## 4. 系统模型

| 组件 | 职责 | 现有或新增 |
| --- | --- | --- |
| `MacMonitorReader` | 从公开接口读取一次实时快照 | 现有 |
| `MonitorHistorySampler` | 在后台按节奏采样，跳过昂贵字段 | 新增 |
| `MonitorHistoryStore` | 写入 SQLite，查询范围，执行保留策略 | 新增 |
| `MonitorHistoryEvent` | 记录睡眠、唤醒、重启、供电和热状态变化 | 新增，并与现有电源历史合并 |
| `MonitorReportBuilder` | 聚合样本，计算峰值、覆盖率和事件 | 新增 |
| `MonitorReportExporter` | 生成自包含 HTML 文件 | 新增 |
| 报告界面 | 选择时间范围、显示覆盖摘要、导出 | 新增 |

### 4.1 数据路径

```text
公开系统接口
  -> MacMonitorReader.readHistory()
  -> MonitorHistorySampler
  -> SQLite history.sqlite
  -> MonitorReportBuilder
  -> self-contained HTML
  -> local save panel
```

### 4.2 信任边界

1. 系统读数是外部输入。
2. 统一日志和诊断报告是不可信文本，只提取固定字段。
3. 派生指标由 Covio 计算。
4. 报告只写本机目标文件。
5. 报告生成不访问网络。

## 5. 状态矩阵

| 状态 | 触发 | 采样行为 | 数据表现 | 报告表现 |
| --- | --- | --- | --- | --- |
| 正常采样 | 应用运行，接电源 | 每 30 秒一次 | 连续样本 | 显示完整时间线 |
| 电池采样 | 应用运行，使用电池 | 每 60 秒一次 | 连续样本 | 标记采样周期变长 |
| 即时事件 | 供电或热状态变化 | 立即补一个样本 | 事件与样本相邻 | 在时间线显示标记 |
| 系统睡眠 | 收到睡眠事件 | 停止定时采样 | 记录睡眠和唤醒 | 显示睡眠区间，不算采集故障 |
| 应用退出 | 应用停止 | 停止采样 | 产生长缺口 | 显示缺口和原因未知 |
| 应用重启 | 再次启动 | 恢复采样 | 新 boot session 或新运行段 | 显示分段 |
| 系统重启 | boot time 变化 | 新 boot session | 旧段结束，新段开始 | 显示重启边界 |
| 时钟跳变 | 墙钟回退或前跳 | 继续采样并标记 | 使用连续时间校验 | 显示时间修正说明 |
| 数据库写失败 | 磁盘满或权限错误 | 继续读，停止落盘 | 内存缓冲有上限 | 明确报告存储失败 |
| 数据库损坏 | 打开或校验失败 | 建立新库 | 旧库改名保留 | 显示历史不可用 |
| 指标不可用 | 硬件或接口不提供 | 该字段为空 | 不写零值 | 显示不可得 |

## 6. 场景

### 场景 A：连续 10 天高强度使用

用户连续使用 Mac。
Covio 全程运行。
电源大部分时间接通。
用户导出最近 10 天报告。

预期：报告包含主要性能时间线、峰值、热状态和事件。
限制：CPU 温度、风扇和频率不出现。

### 场景 B：应用只运行了一天

用户安装 Covio 后立即请求过去 10 天报告。

预期：报告显示约 1 天 Covio 数据。
系统日志可补少量事件，但不能提供连续 CPU、GPU、内存、磁盘和网络历史。
报告不能把缺失的 9 天写成正常。

### 场景 C：睡眠和重启

区间内出现睡眠、暗唤醒、完整唤醒和一次重启。

预期：报告把睡眠区间与采集缺口分开。
重启边界由 boot session 标识。
报告不把睡眠时间算作 Covio 采样失败。

## 7. 成功标准

1. 能区分系统历史、Covio 采样和不可得数据。
2. 能解释 10 天报告需要提前运行 Covio。
3. 30 秒和 60 秒采样策略有成本依据。
4. 14 天保留策略有容量依据。
5. 报告能表达覆盖率、睡眠区间和缺口。
6. 默认不采集用户内容、进程名称和网络载荷。
7. 首版不需要 root、helper 或新增 TCC 权限。
8. 导出报告不访问网络。
