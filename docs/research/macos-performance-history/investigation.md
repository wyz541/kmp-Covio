# 调研、来源与方案矩阵

> 本文件承载调研方法、数据源矩阵、约束、候选方案、源码分析和已知缺口。

## 1. 调研方法

本研究分四步。

1. 复用 `docs/research/hardware-monitoring-capability/` 的实时数据源结论。
2. 查 Apple SDK 和系统手册，确认历史接口、权限和保留行为。
3. 在本机运行只读探针，核对 10 天覆盖、采样成本和存储容量。
4. 对照现有 Covio 监控实现，确定可复用部分和必须新增的部分。

本机环境见 [evidence.md](evidence.md) 的 E-01。
所有探针只读。
验证没有读取用户文件内容。
验证没有保存原始隐私日志。

## 2. 来源范围

| 来源 | 用途 | 限制 |
| --- | --- | --- |
| `MacMonitorReader.swift` | 已有实时指标读取路径 | 只在监控页可见时采样 |
| `MonitorSnapshot.swift` | 已有快照与短历史模型 | 只有 60 个内存点 |
| `MonitorPower.swift` | 已有电源历史与能耗窗口 | 最长 30 分钟或 24 小时 |
| `PowerHistory.kt` | 已有电源事件持久化 | 最长 7 天，最多 200 条 |
| `OSLog.framework` SDK 头文件 | 统一日志 API、权限和轮转语义 | 不能提供连续性能指标 |
| `pmset(1)` | 睡眠、唤醒与电源事件 | 输出是调试接口，不是稳定格式 |
| `/var/log/powermanagement` | 本机旧电源日志文件 | ASL API 已废弃，首版不依赖 |
| `DiagnosticReports` | 崩溃和诊断报告 | 只能补事件，不能补性能时间线 |
| `powermetrics(1)` | CPU、GPU、温度与功耗读取 | 要求 root，首版不采用 |

## 3. 领域模型

### 3.1 术语

| 术语 | 含义 |
| --- | --- |
| 系统历史 | macOS 已经保存，Covio 可以事后读取的记录 |
| Covio 采样 | Covio 运行时主动读取并持久化的指标 |
| 不可得 | 公开接口和当前权限下不能稳定读取的指标 |
| 采集缺口 | 应有样本但没有样本的时间段 |
| 睡眠区间 | 系统处于睡眠或暗唤醒，不要求连续样本 |
| 覆盖率 | Covio 样本覆盖的运行时间与报告范围的比例 |
| 报告事实 | 从样本和事件直接计算出的值，不是故障结论 |

### 3.2 数据单元

| 单元 | 必要字段 |
| --- | --- |
| 样本 | UTC 时间、boot session、供电状态、热状态、指标值 |
| 事件 | UTC 时间、boot session、事件类型、简短原因 |
| 间隔 | 开始时间、结束时间、原因 |
| 系统快照 | macOS 版本、机型、芯片、内存、磁盘总容量 |
| 报告范围 | 开始时间、结束时间、用户选择的最大天数 |

### 3.3 事实、推论和假设

| 类型 | 内容 |
| --- | --- |
| 事实 | 当前监控只保存在内存，容量是 60 个点 |
| 事实 | 当前电源历史是 30 分钟窗口和 24 小时事件 |
| 事实 | 本机统一日志在 10 天前仍有条目 |
| 事实 | `powermetrics` 在普通用户下失败 |
| 推论 | 连续 CPU、GPU、内存、磁盘和网络历史必须由 Covio 自己保存 |
| 推论 | 30 秒采样不会造成明显 CPU 开销 |
| 假设 | 后台采样每天运行 24 小时 |
| 假设 | 报告主要是查看趋势和峰值，不是复现秒级故障 |

## 4. 约束模型

| 约束 | 影响 | 处理 |
| --- | --- | --- |
| macOS 不保留连续指标历史 | 安装后不能重建过去 | 明确说明需要提前采样 |
| 统一日志按空间和时间轮转 | 10 天覆盖不能保证 | 只作为事件补充 |
| 日志缺少结构化契约 | 解析容易随版本变化 | 限定字段，失败时降级 |
| 高频采样影响续航 | 不能沿用实时页的 1 秒节奏 | 后台采用 30 秒或 60 秒 |
| 数据库写入失败 | 报告可能缺数据 | 有界缓冲并显示错误 |
| 睡眠和重启打断采样 | 产生时间缺口 | 使用事件和 boot session 区分 |
| 隐私边界 | 进程、路径和网络信息敏感 | 默认不采集 |
| CPU 温度、风扇和频率受限 | 报告不能展示完整硬件状态 | 明确列为不可得 |

## 5. 控制路径与信任边界

### 5.1 控制路径

```text
后台计时器
  -> 串行采样器
  -> 公开系统接口
  -> 规范化样本
  -> 单事务写入
  -> 保留策略
```

报告路径如下。

```text
用户选择范围
  -> 存储查询
  -> 时间桶聚合
  -> 事件对齐
  -> HTML 模板
  -> 本机文件
```

### 5.2 信任边界

| 边界 | 输入 | 风险 | 控制 |
| --- | --- | --- | --- |
| 系统接口 | 数字、枚举、错误 | 接口变化、空值 | 每项单独降级 |
| 统一日志 | 格式化字符串 | 注入、隐私、格式变化 | 固定 predicate，不渲染原文 |
| 诊断报告 | 文件名和 plist 字段 | 路径和进程信息泄露 | 只计数和分类 |
| 数据库 | 历史样本 | 损坏、部分写入 | WAL、事务、完整性检查 |
| HTML 模板 | 聚合值 | 转义错误 | 所有文本 HTML 转义 |

## 7. 候选方案对比

### 7.1 历史来源

| 方案 | 成本 | 风险 | 成熟度 | 可维护性 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 只读 macOS 日志 | 低 | 10 天不保证，缺少连续指标 | 低 | 低 | 不采用 |
| 只保存 Covio 后台采样 | 中 | 安装前数据无法重建 | 高 | 高 | 采用 |
| Covio 采样加日志事件补读 | 中 | 日志格式可能变化 | 高 | 中 | 采用 |
| 解析旧 ASL 电源文件 | 中 | API 已废弃，文件巨大 | 低 | 低 | 不采用 |

### 7.2 持久化

| 方案 | 成本 | 风险 | 成熟度 | 可维护性 | 结论 |
| --- | --- | --- | --- | --- | --- |
| SQLite3 | 中 | 需要少量 C API 封装 | 高 | 高 | 采用 |
| SwiftData | 低到中 | 模型迁移和查询行为不够透明 | 高 | 中 | 不作为首版存储 |
| JSON 数组 | 低 | 每次重写、损坏恢复差 | 中 | 低 | 只用于配置 |
| 二进制追加日志 | 中 | 查询与压缩逻辑自建 | 低 | 低 | 不采用 |

### 7.3 导出格式

| 格式 | 成本 | 风险 | 成熟度 | 可维护性 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 自包含 HTML | 中 | 用户可能期望 PDF | 高 | 高 | 采用 |
| PDF | 中到高 | 图表和分页调试成本 | 中 | 中 | 后续增加 |
| Markdown | 低 | 交互和图表表现弱 | 高 | 高 | 可作为附加格式 |
| JSON 或 CSV | 低 | 不是可阅读报告 | 高 | 高 | 后续作为附加格式 |

## 8. 目标产品源码分析

分析版本为 `c3045f0142f405f5d2ae9f8cd75a9f4784017f30`。

| 文件 | 现有职责 | 可复用部分 | 缺口 |
| --- | --- | --- | --- |
| `macosApp/src/Hub/Monitor/MacMonitorReader.swift` | 读取 CPU、GPU、内存、磁盘、网络、电源和热状态 | 指标口径与读取函数 | 缺少历史模式，包含不必要进程扫描 |
| `macosApp/src/Hub/Monitor/MonitorSnapshot.swift` | 快照、节奏和 60 点内存历史 | 样本模型和速率计算 | 没有持久化，没有事件 |
| `macosApp/src/Hub/Monitor/MonitorTabView.swift` | 页面可见时以 1 秒或 5 秒采样 | 串行 `MonitorSampler` 模式 | 页面离开即停止 |
| `macosApp/src/Hub/Monitor/MonitorPower.swift` | 电源历史、分钟点、24 小时事件 | 聚合和事件思路 | 窗口过短 |
| `kmpDomain/src/com/wyz/covio/core/PowerHistory.kt` | 电源事件原子 JSON 持久化 | 事件模型和保留策略 | 7 天、200 条，不保存性能指标 |
| `macosApp/src/Platform/MacLoginItem.swift` | 登录项安装与卸载 | 支持后台持续运行 | 用户可关闭 |

现有实现的关键事实：

1. 实时页只在可见时采样。
2. 内存历史是 60 个点，不能跨页面或重启保留。
3. 电源历史最长 30 分钟和 24 小时。
4. 电源事件持久化最多 7 天和 200 条。
5. 后台持续采样必须新增，不能只扩大现有内存数组。

## 9. 采样策略依据

### 9.1 采样周期

| 状态 | 周期 | 原因 |
| --- | --- | --- |
| 接电源 | 30 秒 | 保留短时峰值，CPU 成本可忽略 |
| 使用电池 | 60 秒 | 降低唤醒次数与续航影响 |
| 供电变化 | 立即 | 记录状态改变 |
| 热状态变化 | 立即 | 记录热压力改变 |
| 睡眠 | 停止 | 系统不提供连续样本 |
| 唤醒 | 立即 | 建立新段并记录缺口 |
| 用户打开报告 | 不改变采样 | 报告读取历史，不启动另一套采样 |

实测完整读取一次当前监控快照平均消耗 15.685 ms CPU（E-13）。
30 秒周期摊薄后是 0.052% 单核 CPU，60 秒周期是 0.026%。
后台采样应跳过进程能耗扫描和 top app 计算，所以真实成本应不高于此值。

### 9.2 数据保留

| 项目 | 建议 |
| --- | --- |
| 原始样本保留 | 14 天 |
| 报告最大范围 | 14 天 |
| 默认报告范围 | 10 天 |
| 数据库大小上限 | 64 MiB |
| 清理时机 | 启动、每日一次、导出前 |
| 清理规则 | 先删超过 14 天的样本，再按最旧优先降到上限 |
| 报告导出后的数据 | 默认继续保留到到期，用户可手动清除 |

14 天样本的实测容量为 6.36 MiB（E-14）。
64 MiB 上限为索引、WAL、事件和未来字段增长留出空间。

## 10. 反证和限制

1. 统一日志在 10 天前仍有条目，但 Apple 明确说明日志按时间和空间轮转。单台机器的结果不能升级为平台保证。
2. `pmset -g log` 是调试接口。当前观察约 7 天，不能作为稳定数据契约。
3. 旧 ASL 文件在本机保留 15 天，但 API 从 macOS 10.12 起废弃。文件大，格式旧，不进入产品。
4. `powermetrics` 能提供更细的功耗和温度，但要求 root，不满足首版边界。
5. 采样成本只测了读取器，没有测电池续航、数据库写入和后台计时器。
6. 统一日志读取要求管理员账号。非管理员账号需要降级。
7. 报告无法识别故障原因，只能表达观察值、事件和相关性。

## 11. 已知缺口

| 缺口 | 影响 | 下一步 |
| --- | --- | --- |
| Intel Mac 的 IOKit 键差异 | 电池功率和 GPU 指标可能缺失 | 实现后补机型矩阵 |
| 台式机没有电池 | 电源区只能显示供电状态或空值 | 按能力探测 |
| App Sandbox 下的日志读取 | 可能影响事件补读 | 在当前非沙盒分发路径验证 |
| 10 天连续后台采样 | 还没有实际运行样本 | 实现后做长时验收 |
| 低电量模式下的唤醒成本 | 未实测 | 后台采样真机耗电测试 |
| 报告时间桶的视觉规则 | 未设计 | 与报告界面 PR 一起定 |
