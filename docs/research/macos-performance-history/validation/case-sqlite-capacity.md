## 2. 验证目标

验证以下问题：

1. 14 天、30 秒周期的 SQLite 容量是否足够小。
2. 40,320 条样本的范围聚合是否足够快。
3. 当前设计是否需要额外的预聚合数据库。

## 3. 测试数据

全部为合成数据。
没有用户数据。
没有系统日志。

样本字段：

1. 时间。
2. boot id。
3. 供电状态。
4. 热状态。
5. CPU、GPU 和内存。
6. 磁盘和网络。
7. 电池、功率和显示状态。

配置：

| 设置 | 值 |
| --- | --- |
| SQLite 页面 | 4096 bytes |
| 日志模式 | WAL |
| 同步模式 | NORMAL |
| 表类型 | STRICT |
| 样本数 | 40,320 |
| 时间间隔 | 30 秒 |
| 覆盖 | 14 天 |

## 4. 实际结果

```text
rows=40320
db_bytes=6664192
db_mib=6.36
pages=1627
page_size=4096
```

小时聚合查询结果：

```text
real 0.02
user 0.01
sys 0.00
```

查询内容：

```sql
SELECT strftime('%Y-%m-%d %H', sampled_at, 'unixepoch'),
       round(avg(cpu_usage), 3),
       round(max(cpu_usage), 3),
       round(avg(memory_used / memory_total), 3),
       count(*)
FROM metric_samples
GROUP BY 1
ORDER BY 1;
```

## 5. 结论

1. 14 天样本约 6.36 MiB。
2. 64 MiB 上限足够首版。
3. 40,320 条数据的聚合查询约 0.02 秒。
4. 首版不需要额外维护预聚合数据库。
