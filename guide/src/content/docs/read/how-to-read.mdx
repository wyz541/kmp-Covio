每一页只回答一个问题。章节回答“它为什么存在”。组件页回答“它是什么，怎样工作”。

## 三种页面

### 章节

章节把产品流程、界面和组件连接起来。章节不复制组件细节，只提供通向组件页的上下文。

### 组件页

组件页先给一句话定义，再列功能、状态、无障碍要求和实现映射。需要实例时，截图与组件页放在同一个目录。

### 证据卡

证据卡记录截图、设备、系统、外观、场景、来源提交和 SHA-256。读者可以追溯一张截图来自哪里。

完整的标记和状态含义见[图例与约定](/appendices/legend/)。

## 阅读顺序

1. 读定义。确认页面讨论的对象。
2. 读功能。确认组件解决什么问题。
3. 读状态。确认界面何时变化。
4. 核对真机实例。确认文字与画面一致。
5. 查看限制。确认结论的适用范围。
